# Development

## Setup

Install Rust (stable), Node.js 22 or newer and the [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/)
for your platform. Then install the frontend dependencies:

```sh
cd apps/desktop
npm ci
```

## Running

```sh
npm run tauri dev                                # real hardware
npm run tauri dev -- --features mock-hardware    # simulated devices
```

The `mock-hardware` feature replaces the espflash backend with two simulated devices (`SIMULATED-ESP32-C3` and
`SIMULATED-ESP32-S3`) that have in-memory flash and produce sample serial output. The interface shows a
"Simulated hardware" badge in this mode. Never enable the feature for release builds.

## Checks

These are the checks CI runs:

```sh
# Rust (from the repository root)
cargo fmt --all --check
cargo clippy --workspace --all-targets --features oxidizeesp/mock-hardware -- -D warnings
cargo test --workspace

# Frontend (from apps/desktop)
npm run check
npm test
npm run build
```

`cargo test` also regenerates the TypeScript bindings in `apps/desktop/src/lib/bindings`. Commit them together
with the Rust changes that caused them.

## Tests

- **Rust unit tests** cover address parsing and region validation, error mapping, job state transitions,
  session exclusivity and port renaming, partition tables, backup metadata, settings and the monitor's text
  handling.
- **Workflow tests** in `crates/oxidizeesp-core/src/service/tests.rs` run complete operations against the
  simulated backend: identifying, flashing an ELF (a synthetic RISC-V ELF is generated by the tests), writing
  binaries, backups with checksum comparison, cancellation, erasing, device swaps, monitor exclusivity and
  disconnects.
- **Frontend tests** (Vitest, Testing Library) cover parsing and formatting utilities, ANSI handling, the job
  reducer, device state helpers and the behaviour of confirmation dialogs and disabled actions.

Automated tests never access real serial ports.

## Testing with hardware

Hardware behaviour cannot be covered by CI. When changing hardware-related code, test with at least one board
using a USB-to-UART bridge and one using native USB-Serial-JTAG, and cover: identifying, flashing an ELF,
writing a binary, a full backup, erasing a region, the serial monitor including unplugging and replugging, and
resetting.

## Project layout

```text
apps/desktop/src/lib/bindings     Generated TypeScript types (do not edit)
apps/desktop/src/lib/components   UI components; ui/ contains the primitives
apps/desktop/src/lib/stores       Application state
apps/desktop/src/lib/views        One component per sidebar entry
apps/desktop/src-tauri/src        Tauri commands and application setup
crates/oxidizeesp-core/src        Hardware core and services
```
